# Инструкции для разработки analyses-app

## Состояние проекта

В репозитории есть HTML-демо в `index.html` и начальный Flutter-каркас в `apps/health_app`. Pub workspace объединяет приложение, чистые Dart-пакеты `packages/medical_domain`, `packages/medical_terminology`, `packages/document_domain` и `packages/document_processing` и `packages/cloud_access`, Flutter-пакет `packages/design_system` и адаптер хранения `packages/local_store`. Flutter UI повторяет исходный дизайн Orange of Health: сводка, анализы, профиль, каталоги, доступ и настройки. Для визуального просмотра используется явно обозначенный синтетический snapshot `assets/demo/original_demo.json`, а не подтверждённые медицинские записи. Работают навигация, поиск/фильтры UI и локальные настройки RU/EN и темы. Локальные профиль, ручные результаты, курсы препаратов и измерения сохраняются в Drift/SQLite с историей и outbox. Оригиналы PDF/PNG/JPEG до 20 МиБ сохраняются в SQLite и передаются через минимальный Documents/PostgreSQL в SeaweedFS OSS с проверкой SHA-256; это локальный стенд с bootstrap авторизацией ([ADR 0008](docs/adr/0008-originals-and-documents.md)). Реализован первый локальный/собственный серверный OCR/LLM-конвейер с общим черновиком, ручной правкой и отдельным подтверждением ([контракт и ограничения](docs/document-processing.md)); локальный helper проверен на Mac через CLI, Android/iOS/web local runtime пока отсутствует. К ручным результатам подключён минимальный встроенный [словарь показателей и единиц](docs/terminology.md) с явным выбором и сохранением выпуска. Контракт — в [локальных записях](docs/local-records.md). Сводка/отчёт за период и синхронизация подтверждённых записей через `services/records` реализованы; история, повторы и явные конфликты — в [контракте пункта 6](docs/reports-and-sync.md). Аккаунты email/password, одноразовые коды, восстановление и сессии устройств реализованы в `services/identity`; UI — Настройки → Вход и устройства ([контракт и пределы](docs/accounts-and-sessions.md), [ADR 0012](docs/adr/0012-accounts-and-sessions.md)). Обычный вход не использует bootstrap-токены, оставленные для dev-совместимости. Облачные разрешения и лимиты выделены в `services/entitlements`; расход фиксируют Documents, Records и Processing в собственных транзакциях ([контракт](docs/cloud-access.md), [ADR 0013](docs/adr/0013-cloud-rights-and-quotas.md)). Для Telegram/VK/MAX добавлен simulation-only каркас `services/notifications` и `workers/messenger_delivery` с optional Compose/Ansible deployment; реальные sender, вебхуки и пользовательские привязки ещё не реализованы ([контракт](docs/messenger-integrations.md), [оператор](docs/operations/messengers.md), [ADR 0014](docs/adr/0014-messenger-scaffolding.md)). Остальные каталоги из архитектурных документов — целевая структура.

Рабочее направление — Flutter/Dart для Android, iOS, web и desktop, общее локальное Dart-ядро, UI по MVVM и облачные микросервисы. Основа каркаса (pub workspaces, ChangeNotifier, go_router, ARB и SharedPreferencesAsync для настроек) принята в ADR 0004. Остальные детали стека остаются предварительными, если ADR не фиксирует принятое решение. Хранение оригиналов в SeaweedFS OSS принято в ADR 0003.

SDK: Flutter 3.50.0 / Dart 3.14.0, версия в `.flutter-version`. Dart/Flutter MCP настроен в `.codex/config.toml`; готовность инструментов и ограничения native-платформ описаны в [окружении разработки](docs/development-environment.md).

## Границы реализации

- Медицинская бизнес-логика и общие сценарии находятся в чистом Dart-ядре без Flutter, `dart:io`, FFI и браузерных импортов. Платформенные зависимости подключаются адаптерами.
- Разделяй Domain Model, API/Storage Model, UI State, ViewModel и веса AI-модели. Views отображают состояние; ViewModels вызывают внедрённые сценарии и освобождают подписки. Медицинские правила принадлежат ядру.
- UI-функции взаимодействуют через публичные входы, идентификаторы и навигационные контракты. Не импортируй внутренности соседней функции. Общие визуальные компоненты не зависят от медицинских сервисов.
- Интерфейс поддерживает русский и английский, а также светлую, тёмную и системную тему. Строки берутся из локализации, оформление — из `design_system`; язык и тема сохраняются локально и работают без сети. Язык UI не меняет исходные медицинские данные.
- Мобильный UI поддерживает телефоны, планшеты и складные телефоны. Адаптируй раскладку по размеру окна и данным о сгибе; сохраняй навигацию, ввод и состояние операций при раскрытии, повороте и изменении размеров. Не фиксируй портретную ориентацию по умолчанию.
- Общее локальное ядро — библиотека внутри приложения. Микросервисы — серверные процессы для облачных функций. Локальные сценарии работают без сети и облачной подписки.
- Все серверные сервисы и OCR/LLM runtimes запускаются через Docker/Compose и имеют Ansible для развёртывания и обновления. При добавлении сервиса обновляй образ/сборку, `infra/server/compose.yaml`, `infra/ansible`, миграции, persistent volumes и readiness-проверки; не вводи хостовые процессы приложения в серверный deployment. Решение — [ADR 0010](docs/adr/0010-docker-compose-ansible.md).
- Каждый серверный сервис владеет своими данными. Межсервисные обращения идут через контракты API и событий. Новые сервисы и пакеты выделяй по реальной границе ответственности; не создавай все предложенные каталоги заранее.
- Web учитывается при выборе зависимостей и контрактов. Камера, геопозиция, файлы, фоновая работа и локальная AI-модель имеют платформенные ограничения; отсутствие возможности должно давать явное состояние и доступный сценарий.
- Сохраняй принятую библиотеку состояния и другие локальные соглашения. Существенное изменение границы, протокола или технологии сопровождай ADR с альтернативами и статусом решения.

## Данные и обработка

- Сохраняй исходные названия, значения, единицы, референсы и происхождение отдельно от нормализации. Не объединяй измерения только по похожему названию. Учитывай лабораторию, метод, материал и совместимость единиц.
- Различай дату без времени, точный момент и приблизительный период. Расчёты получают выбранную дату или внедрённые часы; последняя дата демоданных не заменяет текущую дату.
- Локальное изменение и outbox фиксируются одной транзакцией. Повторы, конфликты, удаления и миграции не должны терять подтверждённые данные. Права доступа и квоты повторно проверяет сервер.
- Исходные байты документа неизменяемы. Превью, OCR и повторная обработка создают производные с происхождением. Публикация оригинала требует проверки размера и SHA-256; multipart `ETag` не заменяет SHA-256.
- OCR/LLM и сопоставление терминов создают черновик. Подтверждение пользователем — отдельный переход. Храни редакцию словаря, область действия соответствия и редакцию МКБ; предложение кода не означает подтверждённый диагноз.
- Режим локальной, собственной серверной или внешней AI-обработки задаётся явно. Облачное хранение не означает согласия на внешний AI API; локальный сбой не запускает скрытую отправку.
- Для разработки используй синтетические или надёжно обезличенные материалы. Не добавляй в Git и диагностические логи секреты, реальные медицинские документы, содержимое подписанных ссылок и данные пациентов.

## Навыки

Проектные workflows находятся в `.agents/skills/`:

- `analyses-flutter-feature` — новая UI-функция, MVVM, адаптивность и платформенные возможности.
- `analyses-medical-data` — результаты, единицы, даты, терминология и МКБ.
- `analyses-offline-sync` — локальное хранение, миграции, outbox и конфликты.
- `analyses-cloud-service` — серверный контракт, worker, коннектор или канал доставки.
- `analyses-document-ai` — OCR/ASR/LLM, черновики и оценка качества.
- `analyses-original-storage` — оригиналы, S3/SeaweedFS, загрузки, квоты и восстановление.

Для задачи на стыке областей применяй соответствующие навыки вместе. Специализированный workflow не требует запуска всех остальных навыков, аудитов или инструментов.

В том же каталоге установлены десять официальных Flutter/Dart-навыков; ревизии и хеши зафиксированы в `.agents/official-skills.lock.json`. Примеры библиотек из них сверяй с проектными решениями; не переносись на другой state management или code generation автоматически. Driver extension относится только к отдельной тестовой/debug-точке входа, а сериализация не добавляет Flutter в чистое Dart-ядро.

## Проверка результата

- Документация: проверь относительные ссылки, согласованность статусов и `git diff --check`.
- Dart-пакет: из его каталога выполни форматирование, `dart analyze` и применимые `dart test`.
- Flutter: форматирование, `flutter analyze` и применимые `flutter test`; для затронутого сценария добавь widget/integration-проверку, если она выявляет существенную ошибку.
- Форматирование проверяется командой `dart format --output=none --set-exit-if-changed` с существующими изменёнными Dart-файлами. Если проверка не проходит, отформатируй их и повтори.
- Изменения хранения, синхронизации, доступа и AI-контрактов требуют проверок на характерные сбои из соответствующего навыка. Для исправления ошибки воспроизведи поведение и проверь исправление.
- Выбирай проверки по риску изменения. Для правок текста и оформления не создавай тесты, повторяющие реализацию. Не вводи обязательный полный набор платформенных сборок для любого изменения.
- Проверяй доступность SDK, `pubspec.yaml` и настроенных команд. Пока их нет, не запускай выдуманные команды и не объявляй проверки пройденными. Указывай, что выполнено, что недоступно и какой риск остался. Сборка платформы не равна проверке на устройстве.

## Работа с репозиторием

- Сохраняй чужие изменения. Не включай случайные файлы вроде `.DS_Store` в результат задачи.
- Коммит, push, публикацию, развёртывание и внешние сообщения выполняй в пределах явного поручения. При запросе коммита включай относящиеся к задаче файлы; новая ветка по умолчанию имеет префикс `codex/`.
- Параллельную работу агентов используй при явном запросе на делегирование. Сначала согласуй границы файлов и контрактов; итоговую интеграцию и проверку выполняет ответственный агент.
- В итоговом сообщении кратко опиши поведение после изменения, проверки и существенные ограничения. Обновляй связанные документы, когда меняется архитектура или публичный контракт.

## Code Review Rules

- Отмечай пути, где повтор запроса или доставки создаёт второй медицинский результат, повторное списание квоты или уведомление.
- Отмечай потерю исходных данных, смешение несовместимых измерений и автоматическое превращение AI-черновика в подтверждённую запись.
- Отмечай обход проверки профиля/владельца на сервере, утечку оригиналов через публичные объекты и скрытую отправку документа внешнему провайдеру.
- Отмечай зависимости, делающие общий Dart-контракт недоступным для web или блокирующие локальное сохранение состоянием сети/подписки.
