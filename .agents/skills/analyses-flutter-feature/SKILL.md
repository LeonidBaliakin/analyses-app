# UI-функция analyses-app

Прочитай [UI-архитектуру](../../../docs/ui-architecture.md) и относящийся к функции раздел [общей архитектуры](../../../docs/architecture.md). Пути ссылок рассчитаны от каталога навыка в репозитории.

## Выполнение

1. Найди существующую функцию, библиотеку состояния, навигацию и сборку зависимостей. Если код ещё не создан, реализуй минимальную нужную функцию; выбор основных библиотек зафиксируй как решение с аргументами.
2. Определи команды пользователя и состояния: данные, пустой результат, загрузка, ошибка, локально сохранено/ожидает синхронизации. Для обработки документа отдельно покажи черновик и подтверждение. Используй только применимые состояния.
3. Распредели ответственность: доменные правила и сохранение — сценарии ядра; UI State и команды — ViewModel; отображение, фокус и жесты — View. Передай зависимости извне.
4. Экспортируй публичный вход функции и типизированные параметры навигации. Не связывай экран с внутренней ViewModel соседней функции и не создавай БД/HTTP-клиент/AI runtime в представлении.
5. Для камеры, файлов, геопозиции и AI проверь возможности платформы и состояния разрешений. Отказ, отмена и недоступность имеют явный результат. Долгая задача не теряет сохранённый черновик при закрытии экрана.
6. Используй RU/EN-ресурсы локализации и семантические токены светлой/тёмной темы из design system. Поддержи системный режим темы. Медицинское значение не передаётся только цветом; смена языка не меняет хранимые исходные данные.
7. Адаптируй UI по размеру окна для телефонов, планшетов и foldables. Учитывай безопасные области, сгиб, ориентацию, клавиатуру и увеличение текста. Сохраняй маршрут, выбор, ввод и состояние операций при перестроении; не запускай повторно импорт или AI из-за смены раскладки.
8. Для настройки языка/темы используй общее состояние оболочки и внедрённое локальное хранилище. Настройки действуют без сети и восстанавливаются после перезапуска; отдельные экраны не создают собственные глобальные настройки.

## Проверка

- Проверь существенные переходы ViewModel с подменёнными сценариями, включая ошибку и повтор команды; освобождение подписок проверяй при затронутом lifecycle.
- Widget-проверка должна подтверждать действие и видимый результат. Для затронутого пути проверь RU/EN, светлую/тёмную палитру, компактный и широкий layout, ввод и доступность. Проверяй относящиеся к изменению сочетания из матрицы UI-архитектуры.
- При изменении настроек проверь сохранение выбора без сети и реакцию системной темы на изменение оформления ОС. Для foldables проверь переходы размеров и сгиба без потери черновика и повторных операций; укажи, проверены они эмуляцией layout или на устройстве/эмуляторе ОС.
- При добавлении зависимости с native/FFI проверь web-совместимость. Доступность камеры или локальной модели подтверждается запуском соответствующего адаптера, а не только успешной сборкой.
- Выполни проверки Flutter из корневого `AGENTS.md`, если приложение и SDK доступны; сообщи фактические платформы проверки.

Результат задачи: работающая функция, её публичный интерфейс, проверки значимого поведения и список оставшихся платформенных ограничений.
