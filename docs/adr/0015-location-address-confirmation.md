# Адрес, подсказки и подтверждение местоположения

## Решение

Каталоги лабораторий и врачей используют один `DeviceAccessViewModel`. Местоположение для пользователя — читаемый адрес (`DeviceLocation`), координаты остаются внутренними данными. `AddressLookupGateway` внедряется отдельно от платформенного GPS-адаптера и не добавляет зависимости в медицинское Dart-ядро.

Оболочка приложения открывает подтверждение после завершения знакомства с разделами, не перекрывая его. При первом открытии каталога за запуск приложения выполняется однократная попытка определения позиции с уже выданным разрешением. Автоматическое открытие каталога не вызывает новый системный запрос разрешения; запросить его можно кнопкой определения местоположения. GPS имеет предел 20 секунд, преобразование позиции в адрес — 8 секунд. После получения адреса показываются вопрос **«Вы находитесь здесь?»**, адрес и действия подтверждения/изменения. Пока пользователь не подтвердил адрес, он не становится текущим местоположением каталога. Повторный явный запрос GPS также создаёт предложение с подтверждением.

Если GPS, разрешение, сеть или преобразование координат недоступны, предлагается последний введённый или полученный адрес с тем же вопросом. При отсутствии истории доступен ручной ввод. Последний адрес сохраняется отдельно в SharedPreferences; GPS-координаты и подтверждение сеанса на диск не записываются. Новая сессия — новый запуск приложения, а не возвращение из фона или переключение вкладок. Подтверждение действует для обоих каталогов до конца запуска. После закрытия неподтверждённого окна другой вход в каталог снова предлагает адрес, не повторяя автоматический GPS-запрос.

Ввод адреса поддерживает подсказки от трёх символов, задержку 400 мс, до пяти вариантов и выбор касанием или клавиатурой. Варианты всегда находятся под строкой ввода внутри прокручиваемой формы. Выбор города оставляет префикс «Город, » для ввода улицы; выбор улицы — «Город, улица, » для номера дома. Подпись указывает следующий шаг. Подстановка варианта ещё не назначает текущее местоположение: полное название и координаты варианта применяются после отдельного подтверждения. Запоздавший ответ не заменяет результаты нового запроса. Выбор варианта заполняет поле; действие «Использовать этот адрес» подтверждает его. Без сети остаются последний адрес и произвольный ручной ввод. Ошибка сохранения адреса не отменяет выбор на текущий сеанс и показывается пользователю.

## Поиск адресов и пределы

При подтверждении введённого или восстановленного адреса без координат
`DeviceAccessViewModel` запрашивает его координаты у того же геокодера
(предел 8 секунд). Единственный результат уровня дома с совпадающим полным
адресом или редактируемым названием применяется сразу; при сравнении
игнорируются регистр, `ё/е`, запятые, точки и лишние пробелы. Если геокодер
возвращает другой адрес дома, окно остаётся открытым и предлагает отдельно
подтвердить найденный адрес. Неоднозначные варианты требуют выбора из
подсказок. Результат уровня города/улицы не становится точкой расчёта.
При недоступности сервиса или отсутствии точного адреса ручной текст можно
сохранить без расстояния; координаты по-прежнему не записываются на диск.
Язык запроса берётся из текущего UI. Запоздавший результат после освобождения
ViewModel не применяется.

Текущий адаптер использует [Photon](https://github.com/komoot/photon) и [API поиска и обратного геокодирования](https://github.com/komoot/photon/blob/master/docs/api-v1.md). По умолчанию — публичный демонстрационный `https://photon.komoot.io/`, замена совместимым endpoint задаётся через `--dart-define=ADDRESS_LOOKUP_URL=...` (URL каталога с завершающим `/`). Это внешний сервис: ему передаются введённая строка либо GPS-координаты для получения адреса. В окне выбора есть пояснение и атрибуция Photon/OpenStreetMap. Медицинские записи, профиль и оригиналы в эти запросы не входят; адреса и координаты не выводятся в диагностические логи.

Публичный Photon допускает умеренную нагрузку, но не гарантирует доступность и может ограничивать запросы. Для массового выпуска потребуется согласованный провайдер или собственный экземпляр. Собственный сервер этим изменением не разворачивается. Текущий сценарий не требует API-ключа и сохраняет ручной ввод при ошибке поставщика. Для русского UI используется `lang=default`, сохраняющий местные названия OSM: публичный Photon отклоняет `lang=ru` (HTTP 400). Для английского UI передаётся `lang=en`. Покрытие и источники каталога организаций определяются отдельно от геокодера.

## Альтернативы

- Только системный reverse-geocoder: не даёт общего ввода с подсказками для web/desktop.
- Публичный Nominatim для автодополнения: его политика не допускает такой сценарий.
- Коммерческие карты с ключом: возможная замена адаптера после выбора поставщика; ключи и договор сейчас не настроены.
- Показ координат без подтверждения: не позволяет пользователю проверить понятный адрес и не учитывает перемещение между запусками.

Решение уточняет геолокационную часть [ADR 0005](0005-device-access.md); остальные платформенные разрешения не меняются.

## Проверка Android: 26 ноября 2026

Публичный Photon отвечает **HTTP 403** на стандартный `User-Agent: Dart/3.14 (dart:io)`. Это воспроизведено реальным HTTP-запросом из Android и сравнением одинаковых запросов с Mac: общий Dart UA → 403, идентификатор `OrangeOfHealth/0.1 (address lookup)` → 200. Нативный адаптер передаёт идентификатор приложения для поиска и обратного геокодирования. В web заголовком управляет браузер. Это объясняло «Не удалось определить адрес по GPS» уже после успешного получения координат.

Регрессию покрывают `test/data/address_lookup_test.dart` и Android-проверка `integration_test/location_platform_test.dart`. Последняя использует настоящий HTTP и SharedPreferences Android, но **синтетические координаты**, а не GPS физического телефона. Запуск на тестовом Android: `flutter drive --driver=test_driver/integration_test.dart --target=integration_test/location_platform_test.dart -d <device-id>` из `apps/health_app`. Проверка не вызывается обычным набором unit/widget-тестов и требует сети.
