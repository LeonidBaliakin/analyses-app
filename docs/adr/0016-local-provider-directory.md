# Локальный каталог учреждений и поиск по расстоянию

## Решение

Первый рабочий каталог Санкт-Петербурга и Воронежа поставляется проверенным
снимком публичных фактов внутри приложения. Пакет `provider_directory` — чистый
Dart без Flutter, IO и SDK карт. Он содержит модель организаций, мест приёма,
врачей, предложений исследований, проверку связей, текстовый поиск и расчёт
расстояния по формуле гаверсинусов. Фильтры и сортировка работают без сети,
аккаунта и облачной подписки.

Снимок `2026-11-27.1` включает 37 филиалов, 9 врачей с 11 местами приёма и
59 позиций исследований. Контакты, координаты и привязки врачей проверены по
официальным страницам; ссылки и дата проверки сохраняются. Это подборка,
которая не обещает полноту каталога городов или актуальное расписание.
Подробные источники и пределы — в [реестре](../provider-directory-sources.md).

Один `DirectoryViewModel` хранит город, выбранные анализы, запросы вкладок
и подтверждённую точку поиска. Views используют публичный интерфейс
`device_access` по [ADR 0015](0015-location-address-confirmation.md).
Результат геокодера уровня города или улицы не используется как точка дома.
Произвольный адрес без координат сохраняет возможность просмотра каталога
с явным отсутствием расстояния. GPS и адрес становятся точкой расчёта после
подтверждения пользователем. При новой точке старые расстояния заменяются.
Подтверждение ручного или сохранённого адреса без координат запускает
геокодирование по ADR 0015; выбор подсказки не является обязательным, когда
найден единственный совпадающий адрес дома.

Результаты фильтруются по городу, врачу, типам анализов из словаря, поисковым вариантам и учреждению,
затем сортируются по неокруглённому расстоянию в метрах. При равенстве используется
устойчивый ID места приёма, а отсутствующие расстояния идут последними.
Карточка подписывает расстояние «по прямой». Точка пользователя дальше 100 км
от ближайшего филиала даёт явное состояние вне пилотного поиска; этот радиус
не является определением административной границы города.

Предложение анализа уровня сети и города не подтверждает его наличие в филиале.
Такие результаты помечаются предложением уточнить доступность. Выбор анализа
использует устойчивый ID из отдельного словаря типов исследований в
`medical_terminology`, выпуск `laboratory-tests-2026-11-27.1`. Проверенные
соответствия сети, исходного названия и кода объединяют формулировки в один
пункт; оригиналы и источники сохраняются. Снимок закрепляет выпуск словаря,
неизвестные и неоднозначные формулировки остаются отдельными пунктами.
Это поиск услуги, не изменение словаря показателей или медицинских результатов.
Подробности — в [правилах терминологии](../terminology.md).
У врача с несколькими местами приёма каждый адрес получает своё расстояние.
Карточки ведут на сайт учреждения или открывают телефон; заявка на приём
и доступность слотов не подтверждаются приложением.

К выпуску от 27.11.2026 добавлены спецификации источника: материал, метод,
полный состав панели, отдельная ссылка и дата проверки. Точная привязка панели
валидирует весь набор компонентов; неопубликованное не подменяется предположением.
Карточка позволяет раскрыть эти сведения. Методы СОЭ и панели с плазминогеном
сохраняют отдельные типы; общий тип поиска глюкозы не объединяет результаты.

Для врачей закреплён `medical-specialties-2026-11-27.1`: проверенные формулировки
профиля связываются с отдельными ID специальностей. Поиск учитывает эти варианты,
RU/EN-названия и ФИО с инициалами; фильтр специальности хранит ID. Исходные ФИО,
роль, URL, ID профиля и дата проверки сохраняются. Совпадение имён не объединяет
врачей; несколько адресов одного врача сохраняют общий ID и отдельные расстояния.

## Обновление и границы

Источник снимка — `packages/provider_directory/data/catalog.json`.
`tool/build_provider_catalog.py` встраивает его в библиотеку; проверка ссылок
между сущностями и тесты выполняются до выпуска. В Git попадают публичные
справочные факты, без отзывов пациентов и без описаний их лечения.
Регулярные коннекторы и сервер `provider-directory` остаются следующим этапом
после согласования доступа и условий обновления источников. Нового серверного
процесса и внешнего AI API этот срез не добавляет.

Геокодирование выполняет внедрённый адаптер Photon с атрибуцией OpenStreetMap.
Его доступность не блокирует справочник; для широкого выпуска нужен согласованный
поставщик или собственный endpoint. Пешеходная и автомобильная длина маршрута
требуют самостоятельного адаптера и отдельной метрики сортировки.

## Альтернативы

- Немедленный сбор всего каталога с сайтов: зависит от разрешений, разметки,
  полноты и доступности источников; не даёт проверенного среза без отдельного импорта.
- Карточки только из карт: подходят для адресов, но не подтверждают точный состав
  врачей и исследований в филиале.
- Онлайн-каталог как единственный источник: делает просмотр справочника зависимым
  от сети. В дальнейшем допустим с локальной пригодной копией и версией данных.

## Проверка

Проверяются географические расстояния, неокруглённая сортировка, неизвестная
позиция, город, исходные названия и область предложения анализа, несколько
мест приёма врача, замена точки пользователя, переходы по контактам, RU/EN,
компактная и широкая раскладка. Сценарии подтверждения адреса и запоздавших
ответов геокодера проверяются в общем `device_access`.

## Последующее развитие

[ADR 0017](0017-provider-connectors.md) добавляет реестр, регулярные коннекторы
и удалённое обновление с локальным кешем. Встроенная подборка `2026-11-27.2`
содержит также 14 филиалов МедЭксперт и пять ЦСП; исходный срез этого ADR
и проверенные врачебные/терминологические связи сохраняются.
