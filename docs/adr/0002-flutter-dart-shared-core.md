# Flutter и общее ядро на Dart

Для iOS, Android, web и desktop рассматривается Flutter с общим ядром на Dart. Desktop включает кандидатов Windows, macOS и Linux; обязательные ОС и минимальные версии ещё предстоит определить. Выбор стека предварительный.

Предметная логика и локальные сценарии размещаются в Dart-модулях, работающих внутри приложения. Общий Flutter UI разбивается на независимые функциональные модули по MVVM с Views, ViewModels и моделями состояния и адаптируется под платформу. Камера, файлы, геопозиция, покупки, OCR, ASR и LLM подключаются через платформенные реализации с общими интерфейсами.

Сетевые микросервисы отвечают за облачное хранение, синхронизацию, доступы, подписки, серверную обработку OCR/LLM и внешние API. Уведомления разделяются по каналам, коннекторы — по источникам. Терминология имеет серверный сервис и версионируемую локальную копию для офлайна. Состав ядра и микросервисов описан в [карте модулей](../core-modules.md).

## Следствия

- Повторно используются медицинские правила, сценарии, слой данных и значительная часть UI.
- Для web предусматриваются браузерное хранилище, отдельная настройка офлайн-загрузки и отдельный AI-адаптер.
- Общий формат результата AI не требует одинаковых весов и движков на всех платформах.
- UI и платформенные зависимости отделяются от чистых Dart-модулей ядра.
- Разделение UI описано в [ui-architecture.md](../ui-architecture.md), облачных обработчиков — в [cloud-services.md](../cloud-services.md).
- Оригиналы сохраняются отдельно от распознанных данных; выбор SeaweedFS OSS записан в [ADR 0003](0003-original-documents-seaweedfs.md).
- Исходные названия и коды сохраняются вместе с нормализованными понятиями и редакцией словаря.
- Прикладные серверные сервисы планируются на Dart и переиспользуют подходящие чистые пакеты ядра; серверный фреймворк выбирается отдельно.

Перед окончательной фиксацией проверяются локальная база, импорт документа, работа LLM, отчёт и синхронизация на целевых платформах.
