# ADR 0017: реестр источников и отдельный микросервис на медицинскую сеть

Статус: принято. Дата: 27 ноября 2026 года.

## Контекст

Локальная подборка по ADR 0016 не обновляется с сайтов автоматически. Нужны
управляемый список источников, регулярные задания и независимое обновление
парсеров. Требование продукта: каждый парсер — отдельный микросервис,
закреплённый за определённой медицинской сетью.

## Решение

`services/provider_directory` владеет реестром, расписаниями, заданиями,
публикуемым каталогом и журналом импорта в собственной БД PostgreSQL.
Семь сервисов `connector-invitro`, `connector-helix`, `connector-smclinic`,
`connector-scandinavia`, `connector-sova`, `connector-medexpert` и `connector-csp`
собираются из общего worker-пакета, но имеют разные AOT-точки входа, образы,
ключи, healthcheck и процессы. Парсер и разрешённый origin закреплены в образе;
изменить сеть переменной окружения нельзя. Филиалы одной сети обслуживает её
коннектор. Workers взаимодействуют с реестром только по HTTP и не получают БД.

Реестр выдаёт задание, когда наступил `next_run`; по умолчанию интервал — сутки.
Worker опрашивает только свою очередь каждые 15 секунд. Запись источника
блокируется транзакцией: одновременно работает одно задание на сеть. Lease
действует 120 секунд и продлевается перед страницами. После потери процесса
задание получает новый lease, максимум три попытки; старое завершение отклоняется.
После ошибки или частичного сбора следующий запуск — через час. Настройки,
задания, даты успешных запусков и последняя пригодная публикация переживают рестарт.

Публикация, receipt завершения и событие `DirectoryPublished` в outbox атомарны.
Повтор того же результата возвращает прежний receipt без второго события.
Изменённый результат с тем же job ID отклоняется. Проверяются источник, регион,
версия парсера, URL, связи и резкое уменьшение числа филиалов. Отсутствие записи
на странице не означает закрытие: импорт добавляет/обновляет наблюдения,
автоматических удалений нет. Подтверждённые старые ID и координаты сохраняются.

Публичный каталог содержит проверенные исходные записи врачей и исследований
из поставляемого снимка плюс автоматически полученные филиалы. Новые перечни
врачей, услуг, названий и цен хранятся отдельными исходными наблюдениями.
Категория сайта не становится врачом, совпадение названия не создаёт медицинское
соответствие, а предложение сети не подтверждает услугу в филиале.
Публикация новых мест приёма и соответствий исследований остаётся явной
редакторской операцией над проверенным снимком/словарём; автоматического
утверждения этих связей этот срез не добавляет.

Клиент получает публичный каталог через настроенный `PROVIDER_DIRECTORY_URL`,
проверяет контракт и хранит последнюю пригодную копию локально. При недоступности
сервера доступны кеш и встроенный снимок. Адрес и геолокация пользователя в
запрос каталога не отправляются. В карточках видна дата проверки адреса.

## Получение данных и пределы

Учитываются `robots.txt`, фиксированный origin, ограничения размера/времени,
пауза между запросами и предел числа страниц. Нет браузерного выполнения JS,
обхода HTTP 403, личных кабинетов, отзывов пациентов и внешнего AI API.
СОВА при проверке прямого доступа возвращает 403; каталог исследований ИНВИТРО
отдаёт JS-оболочку. Эти состояния видны как ошибки соответствующих разделов,
а прежние сведения не выдаются за только что полученные.

Новые сервисы включены в optional Compose profile `directory` и Ansible.
Реестр хранится в постоянном томе PostgreSQL основного стека. Readiness проверяет
БД реестра и контакт каждого worker с реестром; она не означает успешность сайтов.
Запуск на внешнем сервере не является частью изменения исходников.

## Альтернативы

- Один процесс со всеми парсерами: проще запуск, но не выполняет требование
  независимых микросервисов и связывает сбои/обновления источников.
- Отдельная БД каждому stateless parser: дублирует владение заданиями; устойчивое
  состояние принадлежит реестру, отдельное хранение worker не требуется.
- Автоматическая публикация всех совпадающих услуг и врачей: не доказывает
  идентичность услуги, специальность и конкретное место приёма.

Контракт API — [provider-directory.yaml](../../contracts/openapi/provider-directory.yaml),
эксплуатация и проверка — [provider-connectors.md](../operations/provider-connectors.md).


Коррекция покрытия: региональная страница ИНВИТРО не является подтверждением
принадлежности всех адресов выбранному городу. Парсер и реестр требуют явного
названия города в адресе. Уже опубликованные адреса вне этого правила
сохраняются отдельно для проверки; корректировка публичного snapshot и outbox
атомарна и идемпотентна.
