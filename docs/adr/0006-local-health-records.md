# ADR 0006: локальные медицинские записи

Статус: принято для первого локального среза, 24 ноября 2026 года.

## Контекст и решение

После каркаса нужен рабочий сценарий без аккаунта и сети: профиль, ручной
лабораторный результат, курс препарата и домашнее измерение. Для этого принимаем
Drift 2.35.4 / SQLite и адаптер открытия drift_flutter 0.3.1. Версии разрешены в
`pubspec.lock`. Основа UI из ADR 0004 сохраняется.

`medical_domain` содержит неизменяемые предметные типы, календарные даты, исходные
значения, проверку периода курса, сценарий сохранения и порт repository. В нём нет
Flutter, JSON DTO, файловых и браузерных импортов. `local_store` владеет SQL-схемой,
DTO и транзакциями. Открытие базы по платформам выполняет приложение.

Используем SQL через custom queries и `OnCreateQuery` Drift без генератора:
сейчас четыре вида записей имеют общий жизненный цикл редакций. Payload — JSON
формата 1, поля владельца, вида, ревизии и удаления индексируются отдельно.
При появлении сложных запросов медицинские таблицы можно выделить миграцией,
сохранив порт ядра. UI получает предметные значения, а не строки SQL.

Один локальный профиль `local-profile` не является аккаунтом. UUID идентифицирует
каждый результат, курс, измерение и команду. Все локальные изменения проходят
через одну транзакцию: текущая редакция, полная история, outbox. Команда содержит
ожидаемую редакцию; устаревшая правка отклоняется, повтор той же команды возвращает
предыдущий результат. Идентификатор команды нельзя переиспользовать с другим
содержимым. Удаление оставляет tombstone и историю; удаление профиля пока закрыто.

В native база хранится в application support. В браузере поставляются локальные
WASM и worker той же версии Drift. Режимы in-memory и unsafeIndexedDb отклоняются:
пользователь получает ошибку открытия и повтор, а не обещание сохранности.

## Альтернативы

- SharedPreferences: подходит настройкам, но не обеспечивает нужные транзакции
  записей, истории и outbox.
- Набор JSON-файлов: требует собственного журнала восстановления и отдельного
  браузерного backend.
- Немедленный серверный CRUD: сделал бы локальное сохранение зависимым от сети.
- Полная нормализованная SQL-модель и отдельный пакет на каждый сценарий:
  пока добавляют границы до появления запросов и самостоятельного жизненного цикла.

## Пределы

Это ручной подтверждённый ввод. Исходные строки и происхождение сохраняются;
нормализация, автоматическая оценка референсов и объединение результатов не
выполняются. Медицинский справочник и AI остаются следующими этапами. Категория
анализа — выбранная пользователем группа оформления, не словарное понятие.

Outbox пока не отправляется и не очищается. Серверная идемпотентность, привязка
аккаунта и разрешение синхронизационных конфликтов ещё не реализованы. Ключи,
шифрование базы, резервное копирование и экспорт требуют отдельных решений.
Настроенное сохранение web-данных не обеспечивает загрузку приложения без сети.
