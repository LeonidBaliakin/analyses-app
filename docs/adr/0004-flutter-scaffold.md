# Основа Flutter-каркаса

Для первого рабочего среза создаём Flutter-приложение, небольшое чистое Dart-ядро и общие визуальные компоненты. Полная медицинская модель, БД, AI и серверы появятся следующими срезами. [ADR 0002](0002-flutter-dart-shared-core.md) сохраняет предварительный статус полного платформенного решения до проверок этих сценариев.

## Решение

- Используем встроенный [pub workspace](https://dart.dev/tools/pub/workspaces): `apps/health_app`, `packages/medical_domain`, `packages/design_system`, один корневой `pubspec.lock`. Версии SDK — Flutter 3.50.0 / Dart 3.14.0.
- UI-функции пока располагаются внутри приложения и экспортируют публичный вход. Самостоятельные пакеты выделяем по появившейся границе ответственности. Не создаём пустые серверные сервисы и все предполагаемые пакеты заранее.
- MVVM: `ChangeNotifier` и `ListenableBuilder`, неизменяемые значения настроек, constructor injection. Сборка зависимостей в `main.dart`; оболочка владеет и освобождает ViewModel и router. Для статических пустых страниц ViewModel не нужна.
- [go_router](https://pub.dev/packages/go_router) обеспечивает маршруты и `StatefulShellRoute.indexedStack`. Разделы имеют устойчивые имена и типизированные назначения. Функции получают callbacks; соседние внутренние Views/ViewModels не импортируют. Web пока использует стандартные hash URLs, не требующие серверного fallback. Universal/App Links не настроены.
- Локализация — ARB, `gen_l10n`, `flutter_localizations`, `intl`. Flutter 3.50 выносит Material/Cupertino-компоненты в `material_ui`/`cupertino_ui`; приложение подключает соответствующие новые делегаты. Генератор SDK ещё выдаёт устаревший список делегатов: приложение его не использует, исключение `deprecated_member_use` ограничено заголовком генерируемых файлов.
- [SharedPreferencesAsync](https://pub.dev/packages/shared_preferences) хранит только язык и тему в одном версионируемом JSON-значении. Применяем выбор после успешной записи, блокируем конкурентные команды, показываем ошибку и допускаем повтор. При неудачном чтении доступны системные значения и повтор загрузки. Медицинские данные требуют отдельного транзакционного хранилища; shared preferences для них не используются.
- `design_system` содержит темы и семантические цвета Material, размеры, пустые состояния и обработку препятствия экрана. Компактная навигация меняется на rail по доступной ширине. При физическом шарнире или сгибе в полуоткрытой позе используем одну свободную панель, сохраняя дерево маршрута. Плоский сгиб в раскрытой позе не ограничивает окно. Раскладка на две панели — следующий шаг для реального списка и деталей.
- `medical_domain` не зависит от Flutter и платформ. Первый тип `CalendarDate` представляет полную григорианскую дату без времени/часового пояса; неполные даты и периоды не выдаются за точные.

## Альтернативы

- Melos/отдельные pub resolution: пока не нужны дополнительные lifecycle-команды и разные графы зависимостей.
- Riverpod/BLoC и DI-контейнер: добавляют зависимости без потребности первого среза; constructor injection достаточно для подмены хранилища и тестирования.
- Собственный RouterDelegate: потребует поддержки URL и сохранения ветвей, которые уже предоставляет go_router. Простой Navigator не закрывает браузерные URL.
- SharedPreferences с кешем: требует учитывать несколько источников изменения; async API читает платформенное хранилище напрямую.

## Следствия и пределы

Каркас можно собирать и проверять независимо от облака. Он не переносит данные HTML-демо и не заявляет медицинское сохранение, офлайн-запуск web, синхронизацию, импорт или AI. Browser cache/service worker, БД и медицинские сценарии требуют самостоятельной реализации и проверок. Bundle identifiers предназначены для разработки; публикация не настроена. В 0.1.1 иконка заменена на Orange of Health.

Проверки и доступные платформы записываются в [структуре проекта](../project-structure.md).
