# Аккаунты, сессии и второе устройство

Реализованный срез от 26 ноября 2026 года. [Решение и ограничения](adr/0012-accounts-and-sessions.md),
[HTTP-контракт](../contracts/openapi/identity.yaml).

Откройте **Настройки → Вход и устройства**. Выберите создание аккаунта, укажите
email, запросите код. Введите восемь цифр из письма, пароль длиной 15–128 символов
и необязательное название устройства. Аккаунт появляется только после проверки email.
На другом устройстве выберите вход с тем же email/паролем.

Права и расход квот видны в блоке [облачных возможностей](cloud-access.md).

После входа отдельно нажмите **Подключить записи этого устройства**. Эта команда
передаёт подтверждённые локальные записи и получает облачные. Текущие очередь,
отказы и конфликты видны на экране синхронизации. Оригиналы подключаются к тому же
аккаунту; их отправка остаётся отдельным действием. Этот шаг не включает внешний AI.

Список устройств показывает независимые сессии, дату создания и текущую сессию.
Можно завершить одну или все. Восстановление: выберите соответствующее действие,
получите новый код, задайте новый пароль и войдите заново. Прежние сессии становятся
недействительны. При недоступном сервере отзыв не объявляется успешным, запрос можно
повторить. Каждую минуту открытое приложение проверяет свою сессию; сервер отклоняет
отозванный токен сразу при следующем обращении.

Выход, истечение сессии и восстановление не удаляют локальные записи, черновики,
оригиналы и outbox. Локальная работа доступна без аккаунта. На совместно используемом
устройстве выход не заменяет блокировку приложения/ОС. Автоматический переход уже
привязанной SQLite к другому аккаунту блокируется; переноса старого bootstrap-владельца
нет. Новое устройство с пустой локальной базой получает профиль из облака.

Native сохраняет сессию в защищённом хранилище ОС; web — в HttpOnly cookie API.
После перезапуска вход восстанавливается при доступном сервере, но передача записей
вновь требует явного подключения. Сбой сети сохраняет credential для повтора и не
блокирует медицинскую базу. Адрес API задаётся сборкой `CLOUD_API_URL`; публичная
сборка должна использовать HTTPS. Для web приложение и API должны быть same-site:
не смешивайте `localhost` и `127.0.0.1`, а origin приложения добавьте в CORS allowlist.

## Локальная проверка

Все письма ниже остаются внутри Mailpit. Из корня репозитория:

```bash
# Только при отсутствии существующей конфигурации:
python3 infra/documents/init_dev.py
python3 infra/documents/init_accounts.py
cd infra/documents
docker compose --profile accounts --profile sync up -d --build documents records identity mailpit
```

Почтовый стенд: `http://127.0.0.1:18025`, API: `http://127.0.0.1:18088`.
SMTP-порт не публикуется. `init_accounts.py` сохраняет прежние credentials/volumes.

```bash
# Из apps/health_app:
flutter run -d chrome --web-port=7357 --dart-define=CLOUD_API_URL=http://localhost:18088/
dart run tool/accounts_smoke.dart
```

Probe создаёт синтетический email в `.test`, читает только локальный Mailpit, использует
два отдельных временных SQLite-файла, проверяет точность исходного значения,
идемпотентный обмен, изоляцию, отзыв и восстановление. Синтетический аккаунт/записи
остаются в dev-стенде, временные SQLite удаляются. Реальные адреса/документы не нужны.

Identity PostgreSQL-тесты работают только с отдельной `identity_tests`; старые тесты
Documents/Records — с `documents_tests`/`records_tests`. Создание этих БД и запуск —
по существующему development workflow. [Результаты](reports/accounts-2026-11-26.md).

## Server/Ansible

`infra/server/compose.yaml` включает Identity и отдельный `identity-db`. Ansible
копирует исходники/lockfile, обновляет persistent bootstrap secrets, собирает образ,
проверяет readiness Identity и доступность auth API через Documents. Для локального
тестового SMTP используется профиль `test-mail` и `analyses_smtp_host: mailpit`.
Для внешнего SMTP задайте `analyses_smtp_*`, отключите insecure SMTP и настройте
HTTPS ingress; cookie Secure включена по умолчанию. Это конфигурация развёртывания,
не разрешение отправить пробное письмо реальному человеку.
