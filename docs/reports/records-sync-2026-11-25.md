192 Dart/Flutter/PostgreSQL теста прошли: medical_domain 11, medical_terminology 8,
document_domain 2, document_processing 6, record_sync 2, local_store 28,
health_app 120, Documents 8, Processing 3, records 4. Дополнительно после уточнения
правил сравнения повторены относящиеся проверки отчёта/экспорта и SQLite.

- Включительные границы дат, исключение чужого профиля/удалений, пересечение курса,
  начавшегося до периода, точность `< 0,0100`, исходное время/offset измерения.
- Группы только по подтверждённому показателю/единице/выпуску и полному одинаковому
  контексту источника. Неизвестные единицы, неполный контекст и одинаковые даты
  не дают выдуманного сравнения.
- Preview, HTML-экспорт с экранированием `<script>` и сохранением исходных строк,
  RU/EN, светлая/тёмная тема, resize/эмулированный шарнир без потери выбранного периода.
- Недоступность выбора файла на mobile и явное копирование полного текстового отчёта.
- Офлайн → сохранение → перезапуск SQLite → сохранённая задержка повторов; потерянный
  ответ после серверного commit восстанавливается без второй записи/события.
- Два устройства, несколько офлайн-редакций, полные локальная/серверная версии конфликта,
  явный выбор локальной или серверной версии, конкурирующее удаление, tombstone,
  отказ устаревшего решения и защита от опоздавшего ответа уже замещённой операции.
- Чужой receipt не подтверждает операцию; порядок ключей JSON не меняет payload.
- Сбой pull откатывает применённые записи/историю и курсор вместе. Смена cloud/account
  binding запрещена; миграция 4→5 не переписывает прежние outbox request. Сохранены
  проверки миграций более старых схем, originals и draft history.
- PostgreSQL проверяет owner/profile/epoch, права и отзыв cloud writes, конкурентный
  повтор/изменённый operationId, CAS edit/delete/явное восстановление, порядок change log.
  Ошибка server outbox откатывает record/receipt/change/cursor одной транзакцией.

## Реальный HTTP и deployment

`apps/health_app/tool/records_sync_smoke.dart` прошёл против изолированного Ansible
стенда на Docker Desktop ARM64, API loopback 18098. На сервере все процессы работают
через Compose; records имеет отдельную БД, не читает таблицы Documents и доступен
клиенту только через его HTTP proxy. Два клиента используют разные файлы SQLite
и deviceId, одну авторизованную облачную область.

Сквозной probe проверил начальное получение без echo в outbox, офлайн-правку и
перезапуск, сохранённый backoff, потерю ACK после реального HTTP commit, повтор,
конфликт двух правок, обе ветви решения, передачу удаления и сохранность истории.
Для тестового результата сервер имеет ровно четыре принятых редакции, без дублей.
Затем синхронизированы пересекающийся курс и измерение; сравнивается полное содержимое
отчётов обоих клиентов: профиль, период, исходные значения, единицы, даты и остальные
поля codec, а не только ID/количество записей.

Ansible обновил существующий стенд без очистки volumes/секретов; проверки Documents,
Processing и нового sync-access прошли (`failed=0`, `unreachable=0`). Dockerfile records
собирает AOT только с общими чистыми Dart-пакетами; Flutter не входит в серверный образ.
Проверены Compose config, синтаксис Ansible, OpenAPI/YAML refs, относительные ссылки,
форматирование изменённых Dart-файлов и `git diff --check`. Статический анализ без
замечаний. Flutter web запущен, hot reload прошёл, runtime errors отсутствуют.

## Что этот прогон не доказывает

Flutter layout проверен widget-тестами, а не на физическом foldable. Новые native
APK/iOS/Windows/Linux сборки и реальная отправка из двух браузерных вкладок не проверялись.
Файловый экспорт проверен через внедрённый адаптер; HTML использует print CSS, отдельного
PDF движка нет. На Android/iOS предоставлен clipboard fallback по явному действию.

Пилотная bootstrap-авторизация не заменяет боевые аккаунты/платежи/врачебные права.
Original bytes, OCR/drafts и локальная история правок не передаются этим sync-протоколом.
Автоматический backup/restore, retention, полевые merge, push и работа после остановки ОС
не реализованы. При восстановлении старого серверного backup оператор должен сменить
epoch, а не продолжать историю под прежними курсорами.
