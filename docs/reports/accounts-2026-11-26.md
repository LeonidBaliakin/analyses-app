# Проверка аккаунтов и сессий, 26 ноября 2026

Только синтетические аккаунты `.test`, записи и локальная тестовая почта.
[Сценарий](../accounts-and-sessions.md), [ADR 0012](../adr/0012-accounts-and-sessions.md).

## Автоматические проверки

147 тестов прошли: health_app 127, Identity 8, Documents 8, Records 4.
PostgreSQL-тесты используют отдельные `identity_tests`, `documents_tests`, `records_tests`.
Проверки Identity включают настоящий production PBKDF2 cost; транзакционные тесты
используют внедрённый более дешёвый verifier.

- Email-код до создания аккаунта, конкурентное подтверждение и повтор без второго
  пользователя, неизвестный recovery-адрес с нейтральным ответом, просроченный код,
  пять неверных попыток и persistent ограничения запросов.
- Независимые сессии двух устройств, невозможность отозвать чужую сессию, текущий
  выход, истечение сессии, сброс пароля с отзывом старых токенов и прежнего пароля.
- Password verifiers с независимыми солями, SHA-256 сессионного токена, шифрование
  mail outbox, откат challenge при отказе outbox, повтор после отказа SMTP и
  восстановление worker с прежним ключом. Payload очищается после доставки.
- HttpOnly/Secure/SameSite cookie, отсутствие bearer в cookie-ответе JSON, CSRF,
  закрытая introspection и запрет ожидаемого чужого owner при смене cookie.
- ViewModel: восстановление, отказ сети с сохранением credential, отзыв, опоздавший
  ответ прошлой проверки, ошибка secure storage, recovery с новым входом.
- Widget: регистрация и явное подключение облака, RU/light и EN/dark, окно 375 px,
  расширение до 1020 px с эмулированным шарниром, текст 140%, сохранение ввода и
  отсутствие повторного запроса кода при перестроении.

## Реальный сервер и браузер

`tool/accounts_smoke.dart` прошёл против dev Docker Compose: PostgreSQL, SeaweedFS,
Identity, Documents, Records и Mailpit. Используются настоящие SMTP-письма, но они
остаются в локальном Mailpit, без внешней доставки. Два клиента с разными SQLite
проходят регистрацию/вход, обмен и повтор без дублей, исходное `< 0,0100`, отказ
чужого профиля/owner, отзыв второго устройства и восстановление. Owner и записи
сохраняются после смены пароля; локальные данные доступны после отзыва сессии.

В браузере вручную через автоматизацию UI проверены реальный вход синтетического
аккаунта, список устройств, восстановление HttpOnly cookie-сессии после reload и
завершение всех сессий. Форма отображается в существующей тёмной теме. Hot reload
прошёл, runtime errors отсутствуют. Компактная раскладка/сгиб проверены widget-тестами.

Android debug APK собран с новым storage-плагином и backup XML. Установка на телефон
не выполнялась; iOS, macOS Keychain, Linux/Windows storage не проверены на устройствах.

## Обновление и эксплуатационные пределы

Ansible обновил существующий локальный `server-check` (Docker Desktop ARM64,
loopback API 18098), добавил Identity БД/образ и test-mail. Повторное обновление
прошло без ошибок (`failed=0`, `unreachable=0`), проверки Documents, Processing,
Records и auth readiness успешны. SHA-256 fingerprints прежних bootstrap credentials
и новых Identity-ключей сохранились. Отдельно проверен upgrade старого bootstrap
файла и повтор: прежние значения не меняются, файл имеет mode 0600.

Публичный HTTPS ingress, реальный SMTP-провайдер, физические телефоны, MFA/passkeys,
удаление аккаунта, перенос старого bootstrap-владельца и backup/restore этим этапом
не проверены/не реализованы. Выход не шифрует и не удаляет локальную медицинскую БД.
