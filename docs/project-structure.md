# Каркас и локальные записи

Состояние на 24 ноября 2026 года. Обычный режим Flutter-приложения работает с собственными локальными записями — [контракт](local-records.md). Через «Посмотреть пример» доступен исходный дизайн и синтетический snapshot `assets/demo/original_demo.json`; он не является медицинской БД и не читает `localStorage` прототипа. HTML-прототип остаётся отдельной демонстрацией.

## Структура

```text
pubspec.yaml                     # Flutter workspace, один pubspec.lock; сервис имеет отдельный lock
apps/health_app/
  lib/
    main.dart                    # bootstrap и constructor injection
    app/                         # владение router/ViewModel, shell, навигация
    data/preferences/            # платформенное хранилище настроек
    data/records/                # открытие native/web SQLite
    features/
      summary/                   # сводка, фильтры, системы
      results/                   # окна показателей и графики
      documents/                 # оригиналы и отдельный список демо-бланков
      processing/                # общий черновик, правка и подтверждение
      reports/                   # сводка периода, полный отчёт, HTML/clipboard
      sync/                      # подключение, очередь, повторы и конфликты
      profile/                   # демо-профиль и его разделы
      settings/                  # контракт, immutable state, ViewModel, View
      records/                   # локальные профиль, результаты, курсы и измерения
    l10n/                        # RU/EN ARB и генерируемые классы
  test/                          # поведение настроек, маршрутов и раскладки
  android/ ios/ web/
  macos/ windows/ linux/         # проекты целевых платформ
packages/
  medical_domain/                # чистые типы, даты, записи и сценарий сохранения
  medical_terminology/           # встроенные выпуски показателей/единиц и точный поиск
  document_domain/              # метаданные оригиналов, целостность и порты
  local_store/                   # Drift/SQLite, DTO, миграции, история, outbox
  design_system/                 # темы, размеры, свободная панель, EmptyState
```

Минимальный словарь показателей и единиц подключён через `medical_terminology` — [контракт](terminology.md). Медицинские правила принадлежат `medical_domain`; он не импортирует Flutter, `dart:io`, FFI или браузерные API. Приложение зависит от ядра через функцию `records`; `local_store` реализует порт хранения. [Локальный срез](local-records.md). Первый тип даты проверяется самостоятельно на Dart VM и в Chrome.

Настройки и состояние поиска/выбора систем имеют ViewModels; локальные жесты и временный ввод остаются в представлениях. В `features/` также появились `capture`, `directory` и `sharing`. `presentation/` содержит типизированный presentation snapshot и общие компоненты его отображения. По мере появления данных функции получают внедрённые сценарии. Функции экспортируют публичный вход и не импортируют `src` соседей. Сборка зависимостей и навигационные callbacks принадлежат оболочке. `design_system` не зависит от медицинских служб и локализации приложения.

## Что работает

- Маршруты `/`, `/results`, `/documents` (оригиналы при внедрённом хранилище; переход к `/results` в демо), `/labs`, `/doctors`, `/profile`, `/sharing`, `/settings`; в браузере используются hash URLs. Неизвестный маршрут даёт переход к сводке. Настройки можно открыть напрямую и вернуться к сводке, если предыдущего маршрута нет.
- Оригинальное плавающее нижнее меню с центральным добавлением и вертикальное меню в широком окне. Выбранный раздел сохраняется при изменении размеров и добавлении/удалении эмулируемого шарнира. Физический шарнир или полуоткрытый сгиб оставляет UI в одной свободной панели; полностью раскрытый экран занимает всю ширину. Ориентация приложения не фиксируется.
- RU/EN; системный язык учитывает порядок предпочитаемых языков, неподдерживаемые языки дают английский. Ручной выбор и возврат к языку устройства доступны в настройках.
- Светлая, тёмная и системная темы. Системная тема реагирует на смену оформления ОС.
- Локальное сохранение языка и темы через SharedPreferencesAsync, обработка ошибки чтения/записи, повтор и блокировка конкурентных изменений. Настройки загружаются до показа приложения.

Решения, альтернативы и особенности Flutter 3.50 — в [ADR 0004](adr/0004-flutter-scaffold.md).

## Команды

Из корня репозитория:

```bash
flutter pub get
dart pub workspace list
```

Из `apps/health_app`:

```bash
flutter gen-l10n
flutter run -d chrome
# Альтернатива на этом Mac:
flutter run -d macos

flutter analyze --no-pub
flutter test
flutter build web --release --no-pub
flutter build apk --debug --no-pub
flutter build macos --debug --no-pub
flutter build ios --debug --no-codesign --no-pub
```

Из `packages/medical_domain`:

```bash
dart analyze
dart test
dart test --platform chrome
```

Агенты выполняют тесты через настроенный Dart/Flutter MCP `run_tests`. Команды выше предназначены также для ручного воспроизведения. Перед проверками нужны установленный SDK из `.flutter-version` и `flutter pub get`. Для отдельного запуска только Dart-пакета можно использовать `dart pub get` при наличии Flutter SDK в `PATH`: workspace разрешает также Flutter-зависимости.

Проверка форматирования из корня:

```bash
dart format --output=none --set-exit-if-changed \
  apps/health_app/lib apps/health_app/test \
  packages/medical_domain/lib packages/medical_domain/test \
  packages/medical_terminology/lib packages/medical_terminology/test \
  packages/design_system/lib
git diff --check
```

## Проверки каркаса и деморежима

Проверки локального медицинского среза перечислены в [локальных записях](local-records.md).

| Проверка | Результат |
|---|---|
| Анализ workspace через MCP и `flutter analyze` приложения | Без диагностик |
| Flutter unit/widget tests | 40 прошли |
| Визуальные снимки нативного UI | 7 проверок при 390×844: сводка, бланки, профиль, настройки, доступ, меню темы в светлой/тёмной палитрах |
| Чистое ядро на Dart VM / Chrome | 4 / 4 прошли |
| Web release | Собрана; Wasm dry run прошёл, отдельная Wasm-сборка не запускалась |
| Android release arm64 | APK 0.1.2 (3) собран; подпись для разработки, запуск на устройстве не проверялся |
| macOS debug | Каркас собран ранее; новый дизайн проверен hot restart/reload, runtime errors отсутствуют |
| iOS debug без подписи | Каркас 0.1.0 собран ранее; редакция 0.1.1 отдельно не собиралась и не запускалась |
| Windows / Linux | Проекты созданы; сборки на соответствующих хостах не проверены |

Widget-проверки включают RU/EN, светлую/тёмную тему, окна 320×640, 844×390, 768×1024, 1440×900, масштаб текста 200%, отключённые анимации, переход компактная/широкая раскладка, эмуляцию шарнира, маршруты, ошибки сохранения, восстановление настроек и системную тему. Добавлены переход 390×844 → 900×840 с плоским сгибом и обратно без потери поиска, вертикальный/горизонтальный полуоткрытый сгиб, применение палитры за первое перестроение и отсутствие обновления `MaterialApp` при начале сохранения. Меню проверяет выбор, Escape, стрелки/Enter, высоту по содержимому и узкое окно при 200% текста в обеих палитрах. Это эмуляция Flutter layout; физические складные устройства и ОС folding-события не проверены. Нативные снимки с настоящими шрифтами и иконками проверяются утилитой `tool/capture_design.dart`. Она запускается через MCP `run_tests` с этим путём и пишет PNG в `/private/tmp/analyses-native-{summary,files,profile,settings,sharing,settings-menu,settings-dark-menu}.png`. Полный screen-reader аудит не выполнялся.

## Что ещё не реализовано

Локальные медицинская БД, профиль, ручные результаты, курсы препаратов и измерения реализованы в функции `records` — [контракт и проверки](local-records.md). Минимальный импорт из оригиналов через OCR/LLM, общий черновик и подтверждение реализован — [контракт и пределы](document-processing.md). ASR, автономный mobile/web runtime, внешний AI API, полноценные дневники, PDF/ссылки доступа врача, полные словари и серверная публикация их выпусков, аккаунты, подписки и остальные облачные сервисы остаются следующими срезами. Минимальный Documents для оригиналов реализован — см. раздел ниже. Кнопки неподключённых сценариев открывают явное сообщение демонстрационного режима и не имитируют успешную запись, передачу, AI или импорт.

Сохранение настроек не означает готовность запуска web без сети: отдельный cache/service worker ещё не настроен. Публикация, подписи и финальные иконки не подготовлены. Полный план — в [архитектуре](architecture.md); окружение и ограничения Simulator — в [настройке SDK](development-environment.md).

## Перенос оригинального дизайна (0.1.1)

Сводка, бланки, профиль, каталоги лабораторий/врачей, доступ и настройки реализованы нативными Flutter-виджетами. Светлая палитра, SVG-иконки и Manrope взяты из `index.html`; для тёмной темы определены соответствующие семантические цвета. Источник шрифта и лицензия — в `packages/design_system/assets/fonts/OFL.txt`, SVG и presentation fixture — в `apps/health_app/assets/`. Исходный HTML не изменён.

Фильтры систем, поиск и история показателей работают над фиксированным синтетическим snapshot. Статусы и исходные значения скопированы из исходного демо; это не реализация нормализации, медицинского сравнения или подтверждения записей. QR в экране доступа кодирует `example.invalid`, подписан как пример и не предоставляет реального доступа.

Android APK 0.1.0 пользователь подтвердил как открывающийся на устройстве. Для новой 0.1.1 проверяются сборка и эмуляция Flutter-layout; запуск этой редакции на физическом Android пока не подтверждён.

Иконка запуска Android, iOS, macOS и web перенесена из геометрии исходного favicon; эталон SVG сохранён в `apps/health_app/assets/brand/icon.svg`. В сборке Android имя приложения — Orange of Health.

## Исправления интерфейса (0.1.2)

Палитры кешируются, уведомления о сохранении не перестраивают приложение, глобальная интерполяция темы отключена. Локальные анимации контролов сохранены. В диагностическом widget-сценарии смена темы требовала 26 дополнительных шагов по 16 ms до стабилизации, после исправления — 13; это шаги виртуальных часов теста, а не измерение FPS или задержки на Android.

Все три выпадающих поля используют управляемый `AppSelect` из `design_system`. Сбой записи оставляет сохранённый выбор и допускает повтор. Плоский сгиб больше не обрезает раскрытый интерфейс до половины окна; физический шарнир и полуоткрытая поза сохраняют свободную панель. APK для проверки: `apps/health_app/build/releases/Orange-of-Health-0.1.2-arm64.apk`.

## Ширина бокового меню (0.1.3)

Пункты бокового меню растягиваются на одинаковую ширину колонки; короткая подпись «Врачи» больше не сжимает выбранную кнопку в капсулу. Исправлен общий Flutter-компонент для Android, web и desktop. Четыре widget-проверки прошли для RU/EN, масштаба текста 100%/200% и ширины окна 900/1440; нативный снимок `rail-dark` и release web визуально проверены, web — в Chrome. Браузерный тестовый раннер завершился по тайм-ауту; его результат не считается пройденным. Собраны `apps/health_app/build/releases/Orange-of-Health-0.1.3-arm64.apk` и `apps/health_app/build/web-0.1.3/`.

## Оригиналы и первый облачный сервис

`document_domain`, адаптер `local_store` (SQLite-схема 3) и функция `documents` реализуют отдельные оригиналы PDF/PNG/JPEG до 20 МиБ. `/documents` открывает рабочий экран оригиналов; прежнее перенаправление к `/results` сохраняется для демо без внедрённого адаптера. `services/documents` — самостоятельный Dart-пакет с собственным lockfile вне Flutter workspace. `infra/documents` содержит локальный Compose для PostgreSQL, SeaweedFS OSS и Documents. [Контракт и проверки](adr/0008-originals-and-documents.md), [запуск](../services/documents/README.md).

Сводка/отчёт и синхронизация подтверждённых записей реализованы в [пункте 6](reports-and-sync.md).
