# Реестр источников и регулярные коннекторы

Реализованы `services/provider_directory` и семь независимо собранных
микросервисов из `workers/provider_connector`. Их общая конфигурация источников —
[sources.json](../../services/provider_directory/config/sources.json).
Решение и граница автоматической публикации — [ADR 0017](../adr/0017-provider-connectors.md).

## Запуск и обновление

В inventory Ansible задайте:

```yaml
analyses_directory_enabled: true
analyses_directory_bind: 127.0.0.1
analyses_directory_port: 18086
analyses_directory_allowed_origins: "https://app.example.org"
```

Обычный [deployment](../../infra/ansible/README.md) копирует build inputs,
добавляет восемь постоянных ключей без ротации прежних секретов, создаёт БД
`provider_directory` и включает profile `directory`. Каждый worker получает
ключ только своей сети. Административный ключ есть только у реестра.
Для внешнего клиента нужен HTTPS reverse proxy; публичные GET не требуют аккаунта.

На подготовленном сервере:

```bash
docker compose --profile directory up -d --build --wait
docker compose --profile directory ps
docker compose --profile directory logs --tail=30 connector-medexpert
```

Обновление одного парсера:

```bash
docker compose --profile directory up -d --build --no-deps connector-medexpert
```

Остановка профиля выполняется явно; выключение флага Ansible не удаляет
контейнеры и данные:

```bash
docker compose --profile directory stop connector-invitro connector-helix connector-smclinic connector-scandinavia connector-sova connector-medexpert connector-csp provider-directory
```

## Расписание, история и состояния

По умолчанию — запуск сразу после первого старта и далее каждые 86400 секунд
после завершения, без календарной привязки к локальному часовому поясу.
Worker опрашивает реестр каждые 15 секунд. После ошибки/частичного сбора — повтор
через 3600 секунд. Потерянный lease переисполняется не более трёх раз с новым
правом завершения. Интервал в административном API — от часа до семи суток.

- `GET /v1/directory/sources`: источники, фактические `enabled`/интервал,
  `nextRunAt`, `lastSuccessAt`, `lastError`, признак работающего задания.
- `GET /internal/sources/{id}/runs`: последние 30 заданий, попытки и результат.
- `GET /internal/sources/{id}/items`: последние исходные наблюдения врачей и услуг.
- `PATCH /internal/sources/{id}/settings`: `{"enabled":true,"intervalSeconds":86400}`.
- `POST /internal/sources/{id}/refresh`: приблизить следующий запуск к текущему
  моменту; уже работающий job не размножается, disabled источник не включается.

Внутренние запросы требуют `Authorization: Bearer <DIRECTORY_ADMIN_KEY>`;
ключ читайте из защищённого окружения, не помещайте в историю команд или Git.
Connector endpoints `claim`/`jobs/{jobId}` принимают только ключ соответствующей сети.
Публичные endpoints не раскрывают ключи/leases. API — в
[OpenAPI](../../contracts/openapi/provider-directory.yaml).

`lastSuccessAt` относится к публикации филиалов. `partial_catalogue` означает,
что филиалы получены, но хотя бы один перечень услуг/врачей не собран целиком.
Причины и числа страниц видны в `catalogueStatus` опубликованного `sourceStates`
и последнем job. `http_403`, `robots_denied`, `markup_changed`, `page_limit`,
`timeout` требуют проверки источника. Они не подтверждают исчезновение учреждения.
Readiness worker означает связь с реестром; неуспешный сайт не делает процесс
неисправным и не вызывает бесконечные рестарты Docker.

Старые строки не удаляются автоматически. Их `checkedAt` сохраняется; каталог
не обещает полный перечень города, актуальные слоты или подтверждённую запись.
Неизвестные координаты не геокодируются автоматически и не заменяются нулями.
Некоторые телефоны закреплены по проверенной подборке с отдельным
`phoneCheckedAt`; обновление адреса не выдаётся за новую проверку телефона.

## Клиент и офлайн

При сборке/запуске Flutter:

```bash
flutter run --dart-define=PROVIDER_DIRECTORY_URL=https://directory.example.org/
```

При старте сначала доступен встроенный каталог, затем локальный кеш и ответ
сервера. Кнопка «Обновить каталог» повторяет запрос. Ошибка не очищает данные,
город, фильтры и точку поиска. Без настройки URL release-сборка использует только встроенный
снимок. Debug-сборки на localhost и desktop автоматически используют порт 18086;
Android-эмулятор — 10.0.2.2:18086. Для воспроизводимой локальной release-сборки
используйте `--dart-define-from-file=config/local-server.json`. Для локальной разработки допускается HTTP localhost/127.0.0.1/10.0.2.2;
для остальных хостов требуется HTTPS. Browser origin явно добавляется в CORS.

## Покрытие парсеров

| Сервис | Филиалы | Исходные каталоги |
|---|---|---|
| ИНВИТРО | HTML офисов СПб/Воронежа | Статический HTML; JS-оболочка отмечается как неполученный раздел |
| Хеликс | Regional SSR JSON, контроль ID региона, исключение соседних городов | SSR предложения исследований с кодами, ценой и региональной пагинацией |
| СМ-Клиника | HTML адресов СПб | Специальности, дочерние списки врачей и таблицы услуг/исследований |
| Скандинавия | HTML отделений СПб | Врачи и лабораторные предложения; запрещённая robots пагинация не обходится |
| СОВА | Адаптер публичных contact-us карточек | Врачи/таблицы; прямой доступ при проверке 27.11.2026 возвращал HTTP 403 |
| МедЭксперт | HTML центров с фильтром Воронежа | Модальные ID врачей, исходные группы и цены услуг |
| ЦСП | Пять контактных карточек Воронежа | Категории → исходные карточки врачей и исследований |

Новые сырые перечни не заменяют проверенные `doctors`/`tests` автоматически.
Для публикации новых мест приёма и словарных соответствий проверяются филиалы,
материал, метод и состав; затем обновляется проверенный снимок и словарь.
Сырые цены сохраняют исходный текст, включая «от», и не обещают окончательную стоимость.

## Проверки

Из каталогов соответствующих Dart-пакетов: `dart analyze`, `dart test`.
Интеграционные тесты реестра требуют отдельной пустой БД с именем на `_test`:

```bash
DIRECTORY_TEST_DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:PORT/directory_test?sslmode=disable dart test
```

Они проверяют конкурентную выдачу, изоляцию источников, повтор завершения,
перезапуск/просроченный lease, недопустимый импорт и сохранение прежних данных.
Fixture-тесты worker используют синтетическую разметку; public live-прогон
следует выполнять отдельно и с штатными ограничениями запросов.

Проверка 27.11.2026: изолированный Compose-стек реестра и семи разных образов
worker прошёл readiness. Живой импорт МедЭксперт завершился с 14 филиалами и
1 678 исходными наблюдениями, ЦСП — с пятью филиалами и 239 наблюдениями;
оба результата без частичных ошибок разделов. После перезапуска реестра
сохранились каталог из 56 филиалов и состояние источников. Проверочный стек
и его отдельный том удалены; постоянный внешний deployment не выполнялся.


## Локальный запуск и остановка всех серверов приложения

На этом Mac профиль включён в стенде `.runtime/server-check` (project
`analyses-server-check`), API каталога — `http://127.0.0.1:18086/`.
Все семь источников включены; расписания и результаты хранятся в PostgreSQL.
При остановленном реестре новые импорты не выполняются. После запуска
просроченные задания и наступившие сроки обрабатываются штатно.

Повторный запуск реестра и парсеров после остановки:

```bash
cd .runtime/server-check
docker compose --profile directory up -d --wait provider-directory connector-invitro connector-helix connector-smclinic connector-scandinavia connector-sova connector-medexpert connector-csp
```

Эта команда использует уже подготовленные файлы deployment и сохранённые тома.
Новая машина требует обычного Ansible deployment. Для web-приложения из
`apps/health_app` можно использовать:

```bash
flutter run --dart-define-from-file=config/local-server.json
flutter build web --release --no-web-resources-cdn --dart-define-from-file=config/local-server.json
```

`--no-web-resources-cdn` включает web-ресурсы в сборку. Это не заменяет
поставку файлов приложения; офлайн-кеш каталога относится к справочным данным.
При остановке всех серверов приложения тома PostgreSQL/SeaweedFS сохраняются;
`down -v` для остановки не нужен. Оба локальных проекта —
`analyses-server-check` и `analyses-documents`; другие проекты Docker
к analyses-app не относятся.


Региональная страница ИНВИТРО содержит также соседние города. Коннектор
публикует в городах пилота только адреса с явным названием выбранного города.
Реестр повторно проверяет это условие. Ранее полученные неподходящие адреса
при старте реестра переносятся из публичного списка в `coverageReviewBranches`:
исходные факты сохраняются для проверки. Исправление и его событие публикации
фиксируются одной транзакцией и не повторяются при следующем рестарте.
Это намеренно консервативный фильтр, а не обещание полного покрытия пригородов.


При полном включении 27.11.2026 завершились первые задания всех семи сетей:
шесть сетей опубликовали филиалы, СОВА вернула `http_403`. После контроля
географии публичный каталог содержит 380 филиалов; 39 записей региональной
страницы ИНВИТРО сохранены отдельно для проверки покрытия. Частичные перечни
врачей/услуг Хеликс, ИНВИТРО, Скандинавии и СМ-Клиники отмечены в реестре.
