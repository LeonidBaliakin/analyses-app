# Локальные медицинские записи

Срез после каркаса, 24 ноября 2026 года. Решение хранения — [ADR 0006](adr/0006-local-health-records.md).

## Пользовательский сценарий

Обычный запуск открывает собственные записи, сначала пустые. Пользователь создаёт
профиль, вручную добавляет результаты, курсы препаратов и домашние измерения,
просматривает детали, редактирует и удаляет записи. История редакций доступна из
деталей и формы. Удаление подтверждается; редакции остаются в БД.

«Посмотреть пример» открывает прежние демонстрационные экраны. Они явно помечены,
не создают медицинских записей и не смешиваются с локальной историей. Каталоги,
доступ врачу, отчёты и графики прототипа остаются демонстрацией. Фото/PDF пока не
становятся медицинским результатом автоматически.

Списки читаются локально. Нет проверки сети, аккаунта или подписки. Ошибка записи
оставляет форму открытой; повтор неизменённой команды сохраняет тот же operationId.
Конкурирующая правка не затирает сохранённую: пользователь может посмотреть историю,
закрыть форму и обновить список перед новой правкой. Ввод сохраняется при изменении
размеров, повороте и сгибе; закрытие изменённой формы требует подтверждения.
Незавершённый ручной ввод при завершении процесса не восстанавливается.

## Контракт данных

- Профиль: имя, необязательная дата рождения, анамнез, аллергии и примечания.
- Результат: исходное название, значение, вид значения, единицы, референс, дата,
  лаборатория, метод, материал, примечания и выбранная группа; необязательная
  подтверждённая пользователем привязка показателя и единицы к выпуску словаря.
- Курс: отдельный ID, препарат, дозировка, режим, назначивший, начало и необязательное
  окончание. Конечная дата не предшествует начальной. Границы включены; курс,
  начавшийся раньше выбранной даты, учитывается. Дата оценки выбирается в UI,
  исходное значение берётся из внедрённых часов.
- Измерение: название, исходное значение, вид значения, единица, источник, дата,
  необязательное местное время с явно введённым смещением UTC и примечания.

Значения хранятся строками без double-конверсии: `0,0100`, `< 0,0100`, текстовый
ответ и отсутствие значения различаются. Пустая единица остаётся неизвестной.
Референсы принадлежат конкретной записи и сохраняются как исходный текст.
Совпадение названий не создаёт связь для сравнения. Ручное сохранение — явное
подтверждение пользователя; происхождение `manual` и время каждой редакции
сохраняются в DTO и истории. Даты без времени представлены `CalendarDate`.

В форме результата доступен [минимальный офлайн-словарь](terminology.md).
Единственный кандидат не выбирается автоматически. Исходные название и единица
сохраняются независимо от понятия. Привязка включает выпуск, устойчивые ID,
снимок контекста и статус выбора; изменение исходных полей сбрасывает её.
Обычная смена языка, выпуска словаря или правка значения не меняет прежнюю связь.
Связь не означает совместимость двух результатов для сравнения.

## Цвета и виджеты

Ключи `AnalysisCategory` устойчивы в формате хранения. UI-соответствие находится в
`features/records/src/category_presentation.dart`; его нельзя восстанавливать из
порядкового номера enum или массива. Цвета определены в `OrangePalette`.

| Раздел | Группы (ключи) | Цвет |
|---|---|---|
| Кровь | `blood`, `iron`, `coagulation` | `#C8364B` |
| Обмен веществ | `carbohydrate`, `lipid`, `vitamin`, `electrolyte` | `#C98410` |
| Гормоны | `hormone` | `#7B4FD0` |
| Органы | `liver`, `kidney`, `gut`, `urine` | `#14907F` |
| Иммунитет и инфекции | `allergy`, `inflammation`, `infection` | `#2B6FD4` |
| Онкомаркеры | `tumor` | `#B83A82` |

Карточки — общий `ColorTile`, сетка — `AdaptiveTiles`, иконки выбираются по ключу
категории. Пустые категории бледнее. В собственных результатах цвет означает группу,
а не медицинскую оценку. Цветные статусы и график из демо не вычисляются для новых
ручных записей, пока не реализованы правила референсов и совместимости измерений.
Цвета, иконки и Flutter-виджеты не входят в медицинское ядро.

## Схема и восстановление

`records` хранит актуальный payload, профиль, вид, ревизию и tombstone.
`record_history` — полный снимок каждой редакции. `outbox` — неизменяемую команду,
её operationId и полученную ревизию. Все три записи фиксируются одной SQL-транзакцией.
Сбой до commit откатывает всё; потерянный ответ допускает повтор команды.
Проверяются профиль владельца и ожидаемая ревизия. Профиль нельзя удалить или
переприсвоить, а tombstone нельзя молча воскресить обычным сохранением.

Версия схемы 3. Миграция из v2 добавляет атомарное хранение оригиналов с BLOB и метаданными; медицинские payload, история и outbox сохраняются без изменений — [ADR 0008](adr/0008-originals-and-documents.md). Тестовая схема v1 содержит текущие записи и outbox; миграция добавляет
историю с исходным снимком и индекс. v1 не была выпущена как медицинское хранилище.
Неизвестная более новая схема не открывается с понижением и не очищается.

JSON payload использует формат 2 только для результата с привязкой к словарю;
формат 1 остаётся для остальных записей. Читаются оба. Старые payload и команды
outbox не переписываются, повтор старой команды сохраняет прежний fingerprint.
Для самой словарной привязки SQL-миграция не требуется. Старый клиент, читающий только формат 1, не поддерживает
открытие результата с привязкой; откат приложения после таких правок не поддержан.
[Контракт и альтернативы](adr/0007-minimal-terminology.md).

Native-адаптер использует `getApplicationSupportDirectory`. Web — Drift/WASM с
постоянным OPFS или безопасным shared IndexedDB. `inMemory` и `unsafeIndexedDb`
отклоняются. Несколько вкладок могут читать устаревший снимок; кнопка обновления
перечитывает БД, а optimistic revision check защищает сохранение. Автоматические
push-обновления списка между вкладками пока не включены. Очистка данных сайта
браузером удаляет локальную БД; оригиналы могут иметь отдельную облачную копию, подтверждённые записи пока не синхронизируются.

Web-ресурсы взяты из [официального релиза Drift 2.35.4](https://github.com/simolus3/drift/releases/tag/drift-2.35.4):

| Файл в `apps/health_app/web` | SHA-256 |
|---|---|
| `drift_worker.js` | `48c950cd8e3bc3cddb34816c860e228be8832bef07a297c27e9907c057ff8162` |
| `sqlite3.wasm` | `e7451780e78c56ff864fe9317a0fbcd6aeb2e8de3beba7f5efd963202f7ec3d9` |

WASM следует отдавать с MIME `application/wasm`. При обновлении Drift проверяются
совместимые worker/WASM и повторяются браузерные проверки. Документация платформы:
[Drift web](https://drift.simonbinder.eu/platforms/web/).

## Проверки

Проверки ядра покрывают точность исходных значений, виды ответа, период курса и
различие даты/времени. SQLite-тесты используют файлы и реальные транзакции:
перезапуск всех четырёх видов записей, повтор команды, конфликт operationId,
ошибка outbox с откатом, устаревшая правка из второго соединения, tombstone,
границы профиля, отсутствие объединения по названию, миграция v1→v2 и отказ downgrade.

Widget/ViewModel-тесты покрывают создание профиля и результата, дату и референс,
ошибку/повтор сохранения, блокировку двойного нажатия, RU/EN, тёмную/светлую тему,
поворот, эмуляцию шарнира, текст 200%, курсы и измерения с явным временем.
Сборки и проверка browser probe фиксируются после выполнения; физические Android,
iOS и складные устройства этим не проверяются.


Проверено на этом Mac: 7 тестов ядра, 8 SQLite-тестов и 94 Flutter unit/widget-теста
прошли; 2 отдельные проверки экспорта снимков прошли, RU light/dark формы просмотрены.
Web release и macOS debug собраны; hot restart macOS прошёл без runtime-ошибок.
Android debug APK собран; установка этой редакции на физическое устройство не проверена.
В настоящем Chrome browser probe использовал `sharedIndexedDb`: повтор команды,
правка из второй вкладки, отклонение устаревшей правки при выключенной сети и
повторное открытие сохранили исходные значения, обе редакции и outbox.

Для воспроизведения browser probe из корня репозитория соберите JS в отдельный
временный каталог, скопируйте туда HTML и ресурсы, запустите локальный сервер:

```bash
mkdir -p /tmp/analyses-browser-probe
dart compile js packages/local_store/tool/browser_probe.dart -o /tmp/analyses-browser-probe/probe.js
cp packages/local_store/tool/browser_probe.html /tmp/analyses-browser-probe/index.html
cp apps/health_app/web/drift_worker.js apps/health_app/web/sqlite3.wasm /tmp/analyses-browser-probe/
python3 -m http.server 8123 --bind 127.0.0.1 --directory /tmp/analyses-browser-probe
```

В одной браузерной сессии откройте `http://127.0.0.1:8123/?run=UNIQUE_ID&phase=seed`,
затем вторую вкладку с тем же `run` и `phase=hold`. В первой откройте `phase=edit`.
Во второй отключите сеть и нажмите «Apply stale edit»: ожидается `PASS conflict`.
Включите сеть и откройте `phase=verify`: ожидается `history=2 outbox=3`.
Новый запуск использует новый `UNIQUE_ID` из букв, цифр и подчёркиваний.
Эти шаги относятся только к отдельной синтетической БД probe.

## Подтверждение документа

[Пункт 5](document-processing.md) добавляет SQLite schema 4, отдельные задания и
черновики с историей. LabResult с documentSource использует payload 3; форматы 1/2
остаются читаемыми и их pending outbox не переписывается. Источник включает SHA-256
оригинала, ID задания/строки, редакцию черновика и исходные поля. Редактор результата
сохраняет это происхождение. Явное подтверждение, записи, история, outbox и маркер
защиты от повтора фиксируются одной транзакцией. Черновик сам по себе не является
медицинской записью. [ADR 0009](adr/0009-shared-processing-draft.md).
