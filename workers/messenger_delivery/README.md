# Messenger delivery scaffold

Один AOT-образ, три независимо настраиваемых контейнера `delivery-telegram`,
`delivery-vk`, `delivery-max`. Адаптер каждого канала выделен в отдельный файл.
`disabled` не забирает задания; `dry_run` проверяет фиксированный RU/EN шаблон и
подтверждает имитацию. Другие режимы, включая `live`, отклоняются при старте.

Нет токенов ботов, внешних HTTP-вызовов и статуса delivered. Контейнеры используют
внутреннюю сеть без маршрута в интернет. HTTP client обслуживает только очередь.
Повторяется только тот же receipt; потерянный lease не означает повтор отправки.

`/health` на внутреннем 8086 показывает канал, режим и счётчики процесса. В
`dry_run` требует успешного poll не старше 30 секунд; в `disabled` проверяет
готовность остановленного адаптера, доступность очереди этим не подтверждается.
Счётчики процесса обнуляются при перезапуске; durable история — в Notifications.
